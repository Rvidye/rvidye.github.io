As a group leader for AstromediComp's Real-Time Rendering batch, I had to build a High Performance Parallel Programming (HPP) demo using CUDA or OpenCL. Around the same time, I was exploring [OpenVDB](https://www.openvdb.org/) and volumetric rendering, and thought building a real-time volume path tracer would be a pretty sick project.

So, I wrote a rather terrible path tracer to traverse VDB volumes and render them in real time using **CUDA–OpenGL interoperability**. The renderer was fairly basic, but it worked!

## Making life unnecessarily difficult

For some reason, I was particularly determined to build this entire project **natively on Linux**.

If you've ever dealt with NVIDIA drivers, CUDA, OpenCL, and graphics development on Linux, you probably know where this is going.

I couldn't get my OpenCL kernels to compile properly, so I ended up using CUDA. But apparently that wasn't enough suffering for me.

I also wanted to use [Dear ImGui](https://github.com/ocornut/imgui) for the interface. Unfortunately, I couldn't find a native X11 platform backend for it at the time, so naturally, I decided to write one myself.

I spent an unreasonable amount of time getting that thing to work. I believe it might have been one of the only standalone X11 backends for ImGui available on GitHub at the time.

It barely worked, though, so perhaps that's for the best.

Maybe someone can get Claude to write a proper one these days. Personally, I'm quite happy developing on Windows now.

## Looking back

Despite all the unnecessary detours, I think this project was one of the things that got me seriously interested in **physically based volumetric rendering**.

I kept coming back to the problem of how light interacts with participating media, which eventually became one of the main motivations behind [FoxRT](/work/foxrt/), my spectral volumetric path tracer.

So I guess all that suffering was worth something after all.
